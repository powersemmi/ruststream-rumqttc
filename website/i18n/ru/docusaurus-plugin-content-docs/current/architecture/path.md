# Путь

Путь одного сообщения MQTT через сервис RustStream: цикл событий, задача соединения, доставка,
обработчик, ответ и подтверждение.

<Diagram name="path" words={words} />

Задача соединения опрашивает цикл событий `rumqttc`, который читает PUBLISH из сокета и
декодирует его. Задача читает тему, находит подписки, к которым относится пакет протокола, как
показывает страница [Демультиплексирование](demultiplexing.md), и отправляет каждой из них
доставку по её собственному каналу. Тема, которая не является корректной строкой UTF-8,
отбрасывается с предупреждением.

[`MqttMessage`](api:ruststream_rumqttc::MqttMessage) разделяет полезную нагрузку с пакетом
протокола, поэтому тело никогда не копируется. Сообщение владеет копией темы и заголовками,
построенными из свойств пакета. Доставка с QoS 1 или QoS 2 также хранит идентификатор пакета,
который нужен её подтверждению. [Контекст](../components/context/index.md), который читает
обработчик, тоже содержит тему.

У канала подписки нет собственного предела. Для QoS 1 и QoS 2 предел задаёт сервер: он отправляет
не больше [Receive Maximum](mqtt/qos.md) неподтверждённых доставок. Пакет, к которому не подходит
ни одна открытая подписка, ждёт подписку, которая откроется позже. Таких пакетов ждёт не больше
1024.

Ответ обработчика кодируется в буфер, и [издатель](../components/publishing/index.md) передаёт
этот буфер `rumqttc` как есть, без копирования. Заголовки становятся свойствами пакета. Публикация
возвращает управление, когда запрос попал в канал запросов клиента, а не когда сервер его
подтвердил.

Доставка завершается после ответа. Её подтверждение проходит через тот же канал запросов, поэтому
уходит после ответа и до DISCONNECT более поздней остановки. Что отправляет каждый исход,
показывает страница [Завершение](settlement.md).

[Бенчмарки](benchmarks/index.md#cost-of-the-code) считают этот путь: инструкции и выделения
памяти одной доставки и одного ответа, включая работу клиента на потоке сервиса.
