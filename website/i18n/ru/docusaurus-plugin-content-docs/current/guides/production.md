# Подключение к промышленному серверу

Управляемый сервис MQTT, например AWS IoT Core, HiveMQ Cloud или EMQX Cloud, требует [учётных данных и TLS](../components/broker/security.md), часто с клиентским сертификатом.
Это руководство настраивает брокер для такого сервиса по окружению развёртывания.

Все настройки развёртывание передаёт в переменных окружения, а сертификаты - файлами.
[`credentials`](api:ruststream_rumqttc::MqttBroker::credentials) задаёт имя пользователя и пароль в пакете протокола `CONNECT`.
Логин внутри URL, например `mqtt://user:p%40ss@host`, тоже работает, и его символы раскодируются из процентной записи; `credentials` имеет приоритет над ним.
В генерируемый документ AsyncAPI они не попадают: он указывает только хост и порт, к которым подключается сервис.

`mqtts://` включает TLS, на порту 8883, если URL не называет другой.
[`tls_ca`](api:ruststream_rumqttc::MqttBroker::tls_ca) - удостоверяющий центр в формате PEM, по которому клиент проверяет сервер.
Клиент доверяет этому центру и никакому другому хранилищу, поэтому URL `mqtts://` без `tls_ca` не даёт сервису запуститься, и ошибка называет `tls_ca`.
[`tls_client_auth`](api:ruststream_rumqttc::MqttBroker::tls_client_auth) добавляет сертификат и ключ клиента для сервиса, который проверяет клиентов по сертификату.

## Свой идентификатор клиента у каждого процесса

Идентификатор клиента - второй аргумент `MqttBroker::new`, и по нему сервер находит сессию.
Второе соединение с тем же идентификатором забирает сессию себе и закрывает первое.
Поэтому у двух реплик сервиса идентификаторы никогда не совпадают: здесь каждая берёт свой из `MQTT_CLIENT_ID`, например имя пода.
Реплики, которые делят работу, вместо этого входят в [группу совместной подписки](topics.md).

## Ограничения

- [`keep_alive`](../components/broker/limits.md) - как часто клиент подтверждает, что жив, на простаивающем соединении. Сервер закрывает соединение, которое молчит в полтора раза дольше. Минимум клиента `rumqttc` - 5 секунд, значение по умолчанию - 60.
- [`max_packet_size`](api:ruststream_rumqttc::MqttBroker::max_packet_size) - наибольший пакет протокола, который принимает сервис. Пакет больше сервер ему не отправит. Значение брокера по умолчанию - 1 МиБ, больше собственного значения клиента, 10 КиБ.
- [`receive_maximum`](api:ruststream_rumqttc::MqttBroker::receive_maximum) ограничивает число доставок с `QoS` 1 и 2 в обработке ([Гарантии доставки](delivery.md)).

Брокер подключается, когда сервис запускается.
Потерянное соединение [восстанавливается](../components/broker/reconnect.md) с задержкой, которая начинается со 100 мс и удваивается до 5 секунд, а когда сервер сообщает, что сессии больше нет, брокер подписывается заново.
Отказ, который не исчезнет при новой попытке, вместо этого завершает задачу соединения: неверные учётные данные, идентификатор клиента, который сервер не принимает, или TLS-рукопожатие, которое сертификаты не проходят.
После этого каждая подписка возвращает эту ошибку.

## Проверка конфигурации

Тесты запускают рабочий `service` с рабочим `broker`, которому даны тестовые настройки, через `TestApp::start`.
Внутрипроцессный сервер читает конфигурацию брокера и отклоняет то, что отклонил бы клиент, не подключаясь к серверу:

- keep-alive меньше 5 секунд не даёт сервису запуститься, и сообщение об ошибке называет минимум клиента;
- URL `mqtts://` без `tls_ca` не даёт сервису запуститься, и ошибка называет `tls_ca`.

Учётные данные и TLS-рукопожатие проверяет только настоящий сервер.
Живые тесты страницы [Security](../components/broker/security.md) проверяют и то и другое на слушателях Mosquitto, которые этого требуют.
